# TANMIA — developer conventions

## Layout
```
src/app          providers: AuthProvider (session restore, my_access), OrgProvider (current org, can(), modules), App, ErrorBoundary
src/routes       AppRoutes (all routes), guards, resolveHome (post-login routing rules)
src/layouts      Shell, OrgLayout (right-side Arabic nav), PlatformLayout
src/components   ui/ (design-system kit), forms/RecordForm (declarative create/edit), ModuleGate
src/features/*   one folder per module: pages/, components/, (optional) api.ts
src/services     db.ts (typed supabase-js wrapper), functions.ts (Edge Functions), storage.ts, programBundle.ts, errors.ts
src/i18n         I18nProvider (tr(ar,en), L(l10n), enumLabel, fmt*), enums.ts (bilingual enum labels)
src/types/db.ts  row types for every table (mirror of supabase/migrations)
supabase/functions/_shared/engine   the analysis engine (pure TS) — imported in React as '@engine'
```

## Rules
- **No fake or sample data** in the UI. Every number comes from the database or the engine.
- Every query filters by `organization_id = org.id` (from `useOrg()`); RLS is the real guard, but filtering keeps queries correct for platform owners who can see all orgs.
- Inserts always include `organization_id: org.id` (and `program_id` when relevant). Codes (`PRG-2026-0001` …) are generated by the database — never send `code` unless the user typed one.
- Gate actions in the UI with `can('module.action')` (RLS enforces the same server-side). Hide create/edit/delete buttons the user cannot use.
- Every list/screen handles loading, empty and error states (`useAsync` + `AsyncView`, `DataTable` props).
- All user-visible text is bilingual via `tr('عربي', 'English')`; enum values via `enumLabel(group, value)`; dates via `fmtDate/fmtDateTime` (Asia/Riyadh).
- Use logical CSS (classes in `src/styles/global.css`); no new colors, no gradients, no new npm dependencies.
- Expert-system behaviour: use the engine (`programHealth`, `compareMaturity`, `assessClaim`, `indicatorPerformance`, `evidenceCompleteness`, `matchExperts`, `detectConflicts`, `buildReport`, `scoreResult`) to guide the user — show findings with `InsightList`, explain rationale, never present a recommendation as an automatic decision.
- Privileged operations go through Edge Functions (`callFunction`), see `docs/EDGE_FUNCTIONS.md`. If a function is not deployed, show the controlled error (`function_unavailable`), never a fake success.
- Never claim causality from a pre/post difference: show `assessClaim(...)` level and its allowed statement.
